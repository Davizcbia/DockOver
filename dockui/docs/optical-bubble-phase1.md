# Optical Bubble：Phase 1 扫描验证

状态：2026-11-23。目前只做了模拟测试和本地浏览器测试，**还没有在真机上测试**。

## 编码：Bubble Code v1（`web/dockdrop-scan/bubble/bubble-code.js`）

光泡的结构从外向内如下（半径 r 以光泡半径为 1）：

| 区域 | r 范围 | 外观 | 作用 |
| --- | --- | --- | --- |
| 静区 | 1.00–1.18 | 暗 | 把光泡和周围画面隔开 |
| 外圈 | 0.93–1.00 | 亮 | 定位：外缘拟合成椭圆 |
| 保护带 | 0.85–0.93 | 暗 | 每个角度上的暗参考 |
| 数据环 | 4 环 | 亮或暗 | 共 168 格：54 / 46 / 38 / 30 |
| 间隙 | 0.33–0.375 | 暗 | 把数据环和内圈分开 |
| 内圈 | 0.29–0.33 | 亮 | 定位：和外圈一起确定透视 |
| 核心 | r < 0.29 | 留给艺术层 | |

**载荷与纠错**
- 同步字：16 位，用来判断方向和镜像。
- 纠错：RS(19,11)，最多纠正 4 个字节；数据经过白化。
- 载荷：版本、标志、64 位一次性密钥、16 位保留。

**解码流程**
1. 用中心与周围的亮度差，粗略找到光泡的位置和大小。
2. 从中心向外打 72 条射线，把外圈边缘拟合成椭圆。
3. 找到内圈边缘，用 Gauss-Newton 拟合一个保持单位圆不变的射影变换（Lorentz boost）。外圈和内圈两个同心圆合在一起确定完整透视。
4. 按每个角度的局部亮、暗参考值给每一格判定阈值。
5. 搜索同步字，确定方向和是否镜像。
6. RS 纠错；失败时用 Chase 软判决，翻转最不确定的 4 格后再试。
7. 有透视时先按透视读取，失败再按仿射读取。

**接受规则**
- 不需要纠错就读出的结果直接接受。8 个校验字节全部碰巧一致的概率是 2^-64。
- 经过纠错的结果，要在 2 秒内读到相同结果两次才接受。

## 页面

**`bubble/show.html`：电脑端测试页**
- 每 60 秒或每次配对后生成新的一次性密钥。
- 显示光泡码，以及备用二维码（扫描页 URL + `#s=密钥`）。
- 作为 host 等待配对。

**`bubble/index.html` + `scan.js` + `worker.js`：手机端扫描页**
- 用 getUserMedia 取像，裁出 400 px 的灰度方块，在 worker 里解码。
- 小光泡时自动换成 2× 缩放。
- 实时显示诊断信息：分辨率、帧率、解码耗时、半径、对比度、透视、镜像。
- 支持 BarcodeDetector 的浏览器上，扫描页也能直接识别二维码。
- 用手机相机扫二维码打开 `#s=` 链接时，页面直接配对。fragment 不会发送到服务器，读取后立即从地址栏移除。

**`bubble/qr.js`：备用二维码编码器**
- 自写，没有第三方依赖。
- byte 模式，M 级纠错，版本 1–6。

## 已验证

**模拟测试：`web/test/bubble.test.mjs`，每种条件 48 次**

相机模拟包括：单应透视、屏幕像素网格摩尔纹、失焦、增益和 gamma、噪声、眩光、镜像。

| 条件 | 结果 |
| --- | --- |
| 正对 | 48/48 |
| 小（90 px） | 48/48 |
| 大（280 px） | 48/48 |
| 倾斜 25–40° | 48/48 |
| 失焦 | 48/48 |
| 摩尔纹 | 48/48 |
| 暗光 | 48/48 |
| 过曝 | 48/48 |
| 眩光 | 48/48 |
| 镜像 | 48/48 |
| 全部叠加 | 48/48 |

- 极限条件：倾斜 45–55°、64 px、失焦 blur 6 都是 48/48。
- 读不出的情况：极暗（gain 0.25 加噪声 0.1）只有 3/48；强眩光（0.9）为 0/48，因为像素已经饱和。
- 误读：0 次读错密钥；300 张没有光泡的干扰图，0 次误读。
- 单帧解码约 12 ms（Node）。浏览器 worker 里约 35 ms（第一帧含 JIT 预热）。

**二维码：`web/test/qr.test.mjs`**
- RS 结果与公开的 HELLO WORLD 1-M 向量一致。
- 格式位与标准表一致。
- 用真实解码器验证要等真机测试。

**本地浏览器（Chromium，dev-server 中继）**
- 页面 canvas 上的光泡解码正确。
- 二维码链接的配对连续成功。
- 合成的 1280×720 相机流：
  - 旋转、压扁、模糊、加噪声的光泡，第 1 帧就读出，随后配对成功；
  - 只有约 50 px 宽的远距离光泡，也是第 1 帧读出。
- 修复了 `pair.js` 的竞态：对方的认证消息可能在 `onmessage` 设置之前到达。之前一方会显示已连接，另一方一直等待。修复后连续 5 次配对，两边都成功。

## 融入液态玻璃的规则（给 Phase 2/3）

- 艺术层只能放在核心、静区以外，以及各元素的高光和色彩里。
- 外圈、内圈、保护带和间隙的亮暗关系不能变。
- 数据格的亮度差不能低于约 0.2（归一化后）。
- 色散和薄膜干涉可以改变色相：解码只读 max(R, G, B)，所以亮度对比必须保留。
- 每一个视觉版本都必须先通过 `bubble.test.mjs`，再在真机上测试。
