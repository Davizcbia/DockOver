# DockDrop 配对光球（Quick Start 风格）——调研与原型 v0.1

状态：**独立视觉原型**（`docky-orb.exe`）。没有网络、没有真实扫描，不启动也不改动 DockOver 的任何现有功能。

## 1. 调研结论

- **Apple 的粒子云格式没有公开。** iPhone 新旧机迁移时的蓝色粒子云由 iOS 系统相机原生识别，Apple 没有发布编码方式，所以这里是我们自己设计的格式（DockOver Orb Code），只借鉴视觉风格。
- **手机系统相机只认标准二维码。** 自定义光球必须用我们自己的扫描器识别：
  - 第一阶段：手机打开 DockOver 的网页扫描页（`getUserMedia` 摄像头 + 本仓库解码器移植成 JS/WASM）。
  - 鸡生蛋问题：手机要先打开这个网页。可选做法：电脑上显示一个很短的局域网地址（如 `http://192.168.1.23:7171`），或第一次用一个小二维码引导，之后都用光球。
  - 以后如果做 iOS / 安卓 App，扫描器内置在 App 里，体验最接近 Apple。
- **电脑和电脑之间**：另一台电脑可以用摄像头扫，但更常见的是：两台电脑在同一局域网发现彼此，一台显示光球，另一台点击"配对"后用摄像头扫；没有摄像头的电脑退回"6 位数字码"确认。

## 2. 编码格式（`src/pairing/orb_code.h`）

| 部分 | 内容 |
|---|---|
| 光球 | 半径 R 的密集粒子球，解码器用它定位和定尺度 |
| 三条码环 | 半径 1.30 R、1.48 R、1.78 R（间距不等，任何缩放都不会让两条环重合，解码器不会锁错尺度），每环 32 格；1 = 一段亮的粒子弧（占格子 78 %），0 = 空 |
| 96 位 | 同步字节 0xB4（8 位，确定旋转和镜像）+ 版本 4 位 + 标志 4 位（bit0 = 支持剪贴板同步）+ 64 位一次性密钥 + CRC-16/CCITT；载荷位经过白化（LFSR），避免长串全亮或全暗 |

- 码环上的粒子沿弧线流动、闪烁，但弧本身不动：画面是活的，编码是静止的。
- 密钥每 60 秒换一次；新码淡入 0.5 s。每环至少 5 段弧、5 段空（`Balanced`），否则重新取密钥。
- 解码器（参考实现，C++，无 Windows 依赖）：
  1. 中心-环绕盒式滤波找光球（抵消眩光渐变，忽略比画面 1/16 还小的亮斑，如文字）。
  2. 联合搜索中心和半径：三条环半径上亮度"弧-空"起伏最大、空隙处最小，并要求"内亮外暗"（有光球在中间）；先在模糊图上粗搜，再在原图上细化。
  3. 求角度相位（相机任意旋转），每格取平均，按每环最大间隔分 0/1。
  4. 尝试全部 32 个整格旋转 × 是否镜像（前置摄像头），校验同步字节和 CRC。
  - 用每像素 RGB 最大值做亮度（光球是蓝色，按亮度公式会比白字还暗）。

## 3. 安全配对（下一阶段，未实现）

- 光球里的 64 位密钥**只经过摄像头**，从不在网络上传输。
- 扫描方和显示方在局域网上用 **PAKE**（计划用 CPace 或 SPAKE2，基于 Windows CNG 的 P-256 / X25519）以这 64 位密钥认证一次密钥交换：看见光球的设备才能完成配对，中间人拿不到会话密钥；在线猜测在 60 秒内不可行（每次失败即作废当前码）。
- 配对成功后双方保存对方的长期设备公钥（"我的设备"），以后 DockDrop 传文件和剪贴板同步直接用这对密钥建加密通道，不再需要扫码。

## 4. 原型 `docky-orb.exe`

- **视觉**：
  - Liquid Glass 卡片：桌面截图做毛玻璃（DXGI 桌面复制，窗口本身不进截图），边缘按圆角 SDF 折射，深色玻璃底，左上高光、右下反光，外侧柔和阴影。
  - 约 2.2 万个球面粒子沿纬线带流动，7 条倾斜轨道粒子流绕球旋转，前近后远（大小、亮度、透视），球后有蓝色辉光。
  - 码环粒子沿弧流动。
  - 外圈有淡淡的尘埃。
- **扫描成功**：码环和尘埃螺旋吸入，球体加速旋转并坍缩成一个光点，闪光，随后出现玻璃气泡和勾，文字淡出后换成"已连接"。
- **全部在 GPU 上**：每个粒子的运动都在顶点着色器里由常量和时钟算出，CPU 每帧不更新粒子；约 3.6 万个粒子 240 fps（p99 4.7–6.6 ms）。
- **操作**：
  - 空格：模拟扫描成功
  - R：换新码
  - Esc 或右上角：退出
  - 拖动卡片任意位置可移动窗口
- **命令行**：`--demo`（3.5 s 后自动成功，循环）、`--secret <hex>`、`--no-desktop`、`--snapshot-seq <dir> --snapshot-after <s> --snapshot-interval <s> --snapshot-count <n>`、`--exit-after <s>`、`--bench-out <file>`
- **启动**：`run_orb.cmd`（build-orb）。

### v0.2 设计调整

- **卡片圆角**：改为连续曲率（超椭圆，|x|^5 + |y|^5 = r^5），和 Apple 的圆角一样，从直边到圆角的曲率是渐变的；为了看起来同样圆，半径 34 → 52 DIP。
- **光球更自然**：
  - 景深：背面粒子更大、更虚、更暗、偏靛蓝，正面锐利、偏青；
  - 流动：叠加缓慢的大尺度涡旋，像流体而不是转盘；
  - 偶尔有火花闪亮；每个粒子周围有一点微光。
- **科幻感**：
  - 玻璃上的光晕颜色在蓝、青、紫之间缓慢漂移；
  - 三条码环下面各有一条极细的 HUD 引导圆，亮度不沿圆周变化，所以不影响解码；
  - 一道扫描光束绕码环缓慢旋转（只改亮度，弧的位置不变）；
  - 玻璃加了极轻的颗粒感。
- **冲击波**：光球坍缩、闪光之后，一圈冲击波从中心扩散到整张卡片，折射背后的桌面，前沿发亮。
- 改完仍然 240 fps（p99 约 5.2 ms），真实渲染截图解码 2/2。

## 6. 手机扫描怎么实现（调研）

**两个硬限制**
1. 网页要用摄像头（`getUserMedia`），必须是**安全上下文**：HTTPS 或 localhost。电脑在局域网上的 `http://192.168.x.x` 不行，自签名 HTTPS 会弹证书警告。
2. HTTPS 网页再去访问局域网里的电脑：
   - Chrome 从 2025 年起用"本地网络访问"权限，用户允许后可以访问私有 IP（Chrome 138 起可用标志测试，Intent to Ship 写的是 Chrome 141），见 [Chrome 博客](https://developer.chrome.com/blog/local-network-access)；
   - iOS Safari 没有这套权限，会被当作混合内容拦截。

**推荐方案：公共 HTTPS 扫描页 + 轻量信令 + WebRTC 局域网直连**
1. **扫描页**：一个静态网页，放在 HTTPS 上（比如 GitHub Pages 或自己的域名），可以"添加到主屏幕"。
   - 摄像头画面在手机本地用 JS 解码，就是本仓库解码器的移植，图像不离开手机；
   - 第一次打开它：卡片角落放一个只含网址的小二维码，或者让用户记住一个短网址。
2. **信令**：一个很小的中转服务（比如 Cloudflare Worker，免费额度够用），只负责交换建立连接的握手信息。
   - 房间号 = SHA-256(密钥) 的前几个字节，服务器拿不到密钥本身。
3. **WebRTC 直连**：手机和电脑用 WebRTC 数据通道直接连接。同一局域网时数据直接走局域网，不经过服务器，链路自带 DTLS 加密。
4. **防中间人**：双方用 64 位密钥对 WebRTC 的证书指纹做 HMAC 并互相核对。中转服务即使作恶也无法冒充（它要在会话的几秒内猜中 64 位密钥）。
5. **电脑端的 WebRTC**：
   - 用 WebView2（Windows 自带的 Edge 内核）跑一段隐藏网页来建立连接，不引入大型原生库；
   - 或者用 libdatachannel，但它会引入 OpenSSL 等依赖。

**其他方案（不推荐作为主路径）**
- 只用局域网（电脑开 HTTP 服务、手机直连）：安卓 Chrome 授权后可行，iOS Safari 不行。
- 原生 App：体验最好，相机识别也最稳，但要上架应用商店，可以作为后续选项。
- 电脑和电脑之间不需要浏览器，局域网发现 + 原生 TCP 即可（不受以上限制）。

**扫描器还要补的能力**：透视矫正（手机斜着拍时码环是椭圆，要做椭圆拟合）；逐帧跟踪（每帧只在上一帧附近细化，几毫秒）；对着屏幕拍会有摩尔纹和过曝，需要用真机测。

## 6b. 手机扫描实现（v0.3，`dockui/web/`）

| 部分 | 内容 |
|---|---|
| `web/dockdrop-scan/orb-code.js` | 解码器的 JS 逐行移植（与 C++ 同一算法）；支持用上一帧结果作提示，实时扫描时只在附近细化 |
| `scan-worker.js` | 在 Web Worker 里解码，页面动画不卡 |
| `index.html / scan.js / style.css` | 全屏相机、圆形取景框（对准后变亮收紧）、Liquid Glass 面板；识别后震动（安卓），粒子聚合、吸入、闪光，然后配对；可"添加到主屏幕"；"选一张截图测试"或 `?image=` 无相机测试 |
| `pair.js` | 房间号 = SHA-256("dockdrop-room-v1" ‖ 密钥) 前 16 字节；WebRTC 数据通道；双方用 HMAC-SHA256(密钥, 角色 + 双方 DTLS 证书指纹) 互相验证 |
| `host.html` | 电脑端测试页（以后由 DockOver 内的 WebView2 承担） |
| `web/dockdrop-signal/` | Cloudflare Worker + Durable Object 中转：每个房间最多 1 个电脑 + 1 个手机，存活 2 分钟，单条消息 ≤ 16 KB，不存储任何内容 |
| `web/dev-server.mjs` | 本地测试服务器（零依赖），同时提供页面和同样协议的中转 |

**验证（本机）**
- JS 解码器：
  - 300 组随机载荷在各种旋转、镜像下全部解对，单比特错误全部被拒；
  - 对原型截图做模拟手机视角（缩小、任意旋转、镜像、模糊、变暗、噪声）：24 次中解出 22 次，每次完整搜索约 175 ms（PC 上的 Node；实时扫描后续帧走提示路径，快得多）。
- 端到端：本地中转 + 两个浏览器标签页（电脑端 host.html、手机端 index.html 用截图代替相机）。识别 250 ms，WebRTC 建连，双方 HMAC 验证通过，两边都显示"已连接"。
- **没测过**：真手机摄像头对着屏幕拍（透视、摩尔纹、曝光）、iPhone Safari 实机、跨设备局域网直连、部署到 Cloudflare。

## 6d. 按 Apple 设计原则审查后的修改（v0.3）

**真机反馈：第二次扫描一直"连接中"**
- 原因：电脑端测试页配对一次就结束了；手机第二次进房间等不到电脑，也没有超时。
- 修改：
  - `pair.js` 加"等待对方"超时（12 s）、可取消（AbortSignal）；中转关闭房间时等待方直接失败，不再挂住。
  - `host.html` 配对后继续等待下一次（真实电脑端在配对窗口开着时也会这样）。
  - 手机端把错误翻译成可操作的提示（电脑没有回应 / 连接超时 / 连不上配对服务 / 验证没有通过 / 正被别的设备配对）。

**电脑卡片**
- 圆角锯齿：原来只在边缘内侧做了半个像素的抗锯齿，超椭圆圆角处的距离场也没有归一化（变化慢于 1 px/px）。现在用场的梯度把距离换算成真实像素，整条 1 px 抗锯齿带横跨边缘，卡片和自己的阴影按覆盖率混合；高光改为约 1.5 px 的柔和线。
- 看不到怎么关：左上角加了可见的玻璃关闭按钮（和 macOS 一致）。悬停变亮，按下内缩；按下后拖开可以取消，松开才执行。
- 找路：副标题直接写出手机要打开的网址，网址单独一行。
- 出现动画：卡片从 0.94 倍放大到原大并淡入（0.45 s，三次缓出，无回弹），粒子一起淡入。

**手机扫描页**
- 状态胶囊：转圈 + 当前步骤（正在打开相机 / 等待电脑回应 / 建立直连 / 验证），连接时可以"取消"；相机模式左上角有关闭按钮，随时回到开始页。
- 取景反馈：连续两帧在同一位置找到光点时，取景圈收紧变亮，提示"找到光点，保持不动"。
- 吸入动画从光点在屏幕上的实际位置和大小开始（原来固定在屏幕中央）；震动和动画在同一帧触发，"已连接"时再轻震一次。
- 面板从底部升起，并从同一方向退出（无回弹）。按钮在按下时就有反馈。
- 字距按字号调整：标题收紧，正文接近 0。
- 支持"减弱动态效果"（改为淡入淡出）、"降低透明度"（实心面板）、"增强对比度"（实心面板 + 明显描边）。
- 动画不依赖 requestAnimationFrame 收尾：页面在后台时也不会卡住配对。

**验证**
- 本机：同一个光点连续扫两次，两次都"已连接"（电脑端测试页持续等待）。
- 电脑端关掉后再扫：先显示"正在等待电脑回应…"和取消按钮，12 s 后提示"电脑没有回应"。
- 电脑卡片 240 fps，截图仍能解码。
- 已重新发布到 GitHub Pages。

## 6e. 动态编码（v0.5，默认）

- **外观**：
  - 码环（同样的 96 位、同样的三圈 32 格）不再同时全亮；
  - 每段弧按自己的节奏短暂"闪"一下：周期 1.2 s，亮约 0.3 s，淡入淡出各约 60 ms；
  - 相位由 (圈, 格) 哈希决定，相邻弧错开；
  - 任意一帧平均只有约 20 % 的弧亮着，看起来是光球不断散出的蓝色火花；
  - 球外的小尘埃移到最外圈之外。
  - 电脑端 `--static` 可切回全亮的旧样式做对比。
- **识别**（`orb_code.h` 的 `TemporalDecoder`，JS 在 `scan.js`）：
  - 每个像素保留最近见过的最亮值（滑动最大值，每 1/30 s 衰减 1.5 %，手机移动不会留下长拖影）；
  - 约一个闪烁周期后，这张"最大值图"里所有弧都在，再用静态解码读出（同样的同步字节和 CRC）；
  - 因此同一个扫描器也能读旧的静态光球，并且第一帧就能读出。
- **定位改进**：
  - 动态码的累积图里，光球本身很密，但外圈有光晕拖影，模糊图上的粗搜索会被拉偏；
  - 现在同时试两个候选：①直接从斑点检测结果精修，②粗搜索后精修；取环得分高的；
  - 另外，"内亮外暗"检查的外侧采样从 1.14 R 移到 1.20 R，避开绕球的粒子流（最远约 1.09 R）。
- **验证**：
  - 模拟 30 fps 手机（轻微手抖、任意旋转、镜像）：40/40 解出，0 次错误，中位 1.00 s，最慢 1.07 s；
  - 真实渲染的 30 fps 序列（三个不同起始时刻）：C++ 和 JS 分别在 30、36、48 帧（1.0 / 1.2 / 1.6 s）解出，结果完全一致；
  - 静态码的单元测试和截图解码不受影响；
  - 扫描页已发布。
