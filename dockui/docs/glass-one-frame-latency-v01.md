# 一帧延迟 DXGI 玻璃路径 v0.1（可选开启，2026-11-20）

## 1. 开关与回退

| 项目 | 内容 |
|---|---|
| 开启 | `LiquidDock.exe --lowlat`，或设置环境变量 `DOCKY_LOWLAT=1` |
| 默认 | 关闭。不开启时，行为与改动前的标准路径一致 |
| 回退 | 去掉开关即可。改动前的源码副本保存在会话暂存区，交接记录中有说明 |
| 延迟日志 | `--lowlat` 下每 60 s 写一行；设置 `DOCKY_LATENCY_LOG=1` 后每 10 s 一行，标准路径也会记录。默认构建不写 |
| 测量专用 | `--dev-isolated` 加 `DOCKY_LATENCY_PROBE_OFFSET=px`：窗口不排除在捕获之外，改为采样左侧 px 处，供外部探针比对 |

## 2. 结构

**1. 分层**（`renderer.cpp`）

- `PrepareUi`：用 D2D 把图标、文字、指示点、诊断信息画进缓存 UI 层（离屏位图）。只在非背景原因引起的帧中重画：`needsFrame_`、动画、诊断。
- `Compose`：只画 GPU 玻璃（plate 加 label 玻璃），叠上缓存层，然后 Present。
- 回退：不满足条件时（菜单、自定义绘制、Smoked、没有背景、label 玻璃失败）返回 `S_FALSE`，调用方改走原来的 `Render`。

**2. 同一设备捕获**（`desktop/duplication.h` 的 owner 模式）

- Dock 的渲染设备成为所在显示器 `SharedDesktop` 复制的 owner，由 Dock 的 UI 线程调用 `PumpOwned` 取帧。
- 同进程的其他玻璃（Control Center、Fan、菜单、Launchpad）仍然通过共享图像获得副本，行为不变。
- 后台线程在 owner 期间暂停。
- 以下情况会交还后台线程：owner 设备无法复制该显示器、切换显示器、设备丢失、退出。

**3. 帧循环**（`main.cpp`）

| 情况 | 做法 |
|---|---|
| 需要出帧（动画或新背景） | 等 waitable → `PrepareUi`（如需）→ `PumpOwned`（近期持续有帧时最多等 2 ms，否则只看一下）→ 发布 ROI → `Compose` → Present |
| 空闲 | 高精度定时器在下一次刷新后 0.4 ms（按 LastPresentTime 对齐）唤醒，取帧并发布；有新背景时只重画玻璃 |

**4. 修正：全屏排除窗口误判**

Genie 最小化覆盖层是一个常显、全屏、被排除在捕获之外的窗口。原来的逻辑把每个桌面变化都当成“排除窗口内部的变化”，于是每次都先做一遍 GPU 比较，相当于发布前多出约 9 ms。

现在 owner 模式下，覆盖显示器 90% 以上的排除窗口不再参与这项判断。标准路径仍有这个问题（见第 5 节）。

## 3. 实测

- **测试环境**：RTX 5070 Ti Laptop、2560×1440、240 Hz、HDR10。用独立测试 Dock（`--dev-isolated`）与用户正在运行的 DockOver 并行测试。背景为暗色测试图，每帧变化。
- **延迟口径**：从“桌面图像上屏”（`LastPresentTime`）到“Dock 显示该图像的帧上屏”（DXGI frame statistics）。实验室已用外部探针标定：1.81 个刷新周期对应 1 帧背景滞后，2.81 对应 2 帧。

| 场景 | 标准路径 | 一帧路径 |
|---|---|---|
| 背景每帧变化，Dock 静止 | 14.9 ms（3.57 个刷新周期），每秒约 55 张新背景 | **7.7–8.4 ms（1.84–2.02 个刷新周期）**，每秒约 235 张 |
| 同上，持续动画（`--continuous`） | 25.2 ms（6.05 个刷新周期），每秒约 69 张 | **7.56 ms（1.81 个刷新周期，99.8% 为 2 个）**，每秒约 235 张 |
| Wallpaper Engine 极光壁纸 | 22.2 ms（5.33 个刷新周期） | **8.27 ms（1.99 个刷新周期）** |
| 动画帧率 | 239–240 fps | 238–240 fps。启动后首秒有一次 49 ms 间隔，与 Launchpad 启动预热重叠 |
| Dock CPU，背景变化 / 静止桌面 | 236 / 31 ms/s | 272 / 25 ms/s |
| Dock GPU，背景变化 / 静止 | 5.23% / 0.18% | 4.51% / 0.10% |
| DWM GPU，背景变化 | 8.01% | 7.90% |
| 视觉对比（同场景截图逐像素比较） | — | 平均差 0.006，最大 7/255，59,000 个像素中没有一个差值超过 8 |
| 单元测试 | — | 28 个可运行测试全部通过（另有 4 个需要样例文件，未运行） |

捕获一帧的物理下限是 1 个刷新周期，0 帧不可能实现。现在的约 1.8 个刷新周期，就是“背景滞后 1 帧”再加上本次合成到屏幕的时间。

## 4. 保留的机制

- 捕获排除：`WDA_EXCLUDEFROMCAPTURE` 不变。
- HDR：FP16 加 SDR 白电平转换不变。转换在 owner 的上下文上执行，执行后会恢复 RS 状态。
- 其他：dirty rect、只复制被关注区域、`Fresh`、自身窗口的 GPU 比较，全部保留。
- 反作弊：只使用 DXGI、D3D11、DComp 公开 API。不注入任何进程，不修改系统、内核或驱动。

## 5. 未验证 / 后续

- 多显示器：本机只有一台显示器。owner 交接代码已写好，但没有实测。
- 设备丢失、显示模式变化、锁屏或 UAC 安全桌面导致的复制中断：代码路径与原来相同，但没有实机触发测试。
- 动画时偶尔出现单帧 11.6 ms 间隔，出现在一次运行中，原因待查。
- 标准路径同样受全屏排除窗口误判影响（2–6 个刷新周期）。是否在默认路径也启用第 2 节第 4 项的修正，待决定。
- 正式版默认开启前还需要：设置界面的开关、在用户常用环境中长时间运行、多显示器实测。

## v0.2 更新（2026-11-20 下午）

### 开关

- 新增 Settings › General › **Low latency glass**（设置键 `dock.lowLatencyGlass`，默认关闭）。
- 切换后立即生效，不需要重启 Dock：
  - 关闭时，桌面复制交还给后台线程；
  - 开启时，Dock 的渲染设备重新接管。
- 命令行 `--lowlat` 或环境变量 `DOCKY_LOWLAT=1` 会强制开启。
- 实测：运行中来回切换 4 次，无卡死，正常退出。

### 修复与改进

| 项目 | 内容 | 影响路径 |
|---|---|---|
| Genie 全屏覆盖层误判 | 覆盖显示器 90% 以上的排除窗口不再算作“自身重绘”。设置 `DOCKY_KEEP_FULLSCREEN_EXCLUDED=1` 可恢复旧行为 | 两条路径 |
| 比较时让路 | 自身窗口重绘触发的 GPU 比较还在进行时，如果窗口外有真实的背景变化，就放弃比较，立即发布新帧 | 两条路径 |
| 取帧不再阻塞 | 不再用带超时的 `AcquireNextFrame`（内核等待会按系统计时器取整，最长约 15 ms），改为非阻塞查看，再用高精度计时器每 0.25 ms 看一次，最多 2 ms | 一帧路径 |
| 动画期间推迟后台工作 | 状态刷新（2–6 ms）和回收站检查（约 1 ms）推迟到动画结束，最多推迟 5 s | 两条路径 |
| 连续背景的节奏 | 只有当上一次刷新也带来了新背景时，才按动画方式逐帧渲染；较慢的来源（Wallpaper Engine）走空闲定时器，取到帧后在同一轮立即绘制 | 一帧路径 |
| owner 交接卡死 | `SetOwner` 等待后台线程时会被一直抢先，导致 Dock 卡住。现在先让后台线程停下，再完成交接 | 一帧路径 |
| 测量日志 | 仅在测量模式下记录：超过 3 ms 的后台轮询逐步耗时，以及长帧前后各阶段（消息、等待、UI 层、取帧、绘制）的耗时 | — |
| 故障注入（仅 `--dev-isolated`） | `DOCKY_TEST_DUP_LOST_AFTER=n`：模拟桌面复制丢失（ACCESS_LOST）；`DOCKY_TEST_DEVICE_LOST_AFTER=n`：模拟设备被移除 | — |

### 实测（240 Hz，HDR10）

延迟单位：ms，括号内为刷新周期数。

| 场景 | 今天开始时（标准路径） | 标准路径（v0.2） | 一帧路径（v0.2） |
|---|---|---|---|
| 背景每帧变化，Dock 静止 | 14.9（3.57） | 8.60（2.06） | **7.63（1.83）**，98% 为 2 个刷新周期 |
| 同上，持续动画 | 25.2（6.05） | 11.7（2.81） | **7.54（1.81）**，100% 为 2 个刷新周期 |
| Wallpaper Engine 极光壁纸 | 22.2（5.33） | 8.7–8.9（2.08–2.14） | **8.1（1.93）** |
| 持续动画的帧率 | 240 fps | 239.9 fps，2380/2381 次 Present，最长间隔 10.6 ms | **240 fps，2380/2380 次 Present，最长间隔 6.6 ms** |
| Dock CPU / GPU，背景每帧变化 | 236 ms/s / 5.2% | 436 ms/s / 7.7%（每秒处理的新背景从 55 张增加到约 234 张） | **186 ms/s / 4.0%** |
| Dock CPU / GPU，接近静止的桌面 | 31 ms/s / 0.18% | 37 ms/s / 0.45% | 68 ms/s / 0.70%（Dock 上方区域有小幅变化时会逐帧重画） |

| 恢复场景（模拟） | 结果 |
|---|---|
| 桌面复制丢失 | 1 ms 内重建 |
| 设备被移除 | 42 ms 内重建设备，67 ms 内重新接管复制；之后背景延迟仍为 1 帧 |

| 真实的驱动重置 | 不安全，不做 |
| HDR 关闭（SDR） | 需要更改系统显示设置 |
