# Optical Bubble：Phase 2 视觉原型

状态：2026-11-23。这一版是不带编码的液态玻璃球，只做视觉。

- Phase 1 的 Bubble Code v1 和扫描页保持原样，这次没有改动。
- 新程序是 `docky-bubble.exe`，代码在 `src/pairing/bubble_main.cpp` 和 `shaders/bubble.hlsl`。
- 渲染方式：D3D11 像素着色器逐像素光线追踪，复用 Docky 已有的桌面复制（DXGI desktop duplication）作为背景。
- 窗口设置了"不进入截图"，所以球体折射不到它自己。

## 实现了什么（都已在截图里看到）

| 要求 | 做法 |
| --- | --- |
| 厚度和体积 | 球体是真正的三维形状。光线在正面折射进入，穿过内部，到背面再折射出来，再去读取背后的画面。内部的光程长度决定吸收（Beer-Lambert），越厚的地方越蓝。所以背景在球里是倒过来、缩小的，和真实玻璃球一样。 |
| 动态背景折射 | 默认读取窗口后面的实时桌面。`--image` 加 `--scroll` 可以让背景移动，折射会同步跟着变。 |
| 局部色散 | R、G、B 三个颜色通道各用自己的折射率，各走各的路径（1.372 / 1.384 / 1.401）。色散只出现在光线偏折大的地方：边缘和涟漪上。 |
| 焦散 | 主光被表面曲率汇聚后，落在球体内侧远端；加上球透镜在背光一侧产生的亮弧。都随涟漪流动。 |
| 薄膜干涉 | 肥皂膜光程差公式。只在局部区域、反射光里出现，在掠射角的轮廓光下最明显（右下角的彩色高光）。 |
| 液体运动 | 低阶表面模态（呼吸和表面张力造成的摆动）加上较小的鼓包。涟漪是从撞击点沿球面扩散、逐渐衰减的波包，撞击点会不断刷新。内部有慢慢上升的小气泡。不是整体旋转，也不是预录视频。 |
| 实时 | 在 544×544 px、半径 170 的窗口里，能稳定跟上 240 Hz 显示器。这只是帧间隔统计，没有单独测量 GPU 耗时。 |

**录屏**：`docs/media/optical-bubble/index.html`，逐帧截图，按 15 帧/秒回放。

**运行**：
- `docky-bubble.exe`：实时桌面背景
- `docky-bubble.exe --studio`：影棚灰背景
- `docky-bubble.exe --image <图> --scroll 90`：移动的图片背景

## 编码怎么融入（下一阶段的研究方向，还没实现）

解码器只需要稳定的局部亮度对比，而这些亮度结构可以由玻璃本身的光学特性产生：

1. **定位结构用玻璃自身的光学特征来做。**
   - 外圈可以换成球体轮廓处的全反射亮环：这本来就存在，只需要让它连续、足够亮。
   - 内圈可以换成焦散的亮环。
   - 需要用模拟测试验证，这两个特征在背景变化时是否足够稳定。
2. **数据格用"光学密度"来表达。** 例如在球的内部放一层薄薄的、带图案的高折射或高吸收介质，像玻璃里悬浮的一层刻花。
   - 亮格可以是"透光、汇聚"的区域，暗格是"吸收、散射"的区域。
   - 背景变化会改变亮度，但解码器用的是局部参考，所以影响有限。
   - 这一点需要实测。
3. **扫描时可以动态调整。** 平时以艺术效果为主。检测到正在配对时（扫描页打开，或配对窗口处于前台），把编码层的对比度升到可解码的水平。
4. **所有方案都要先过 `bubble.test.mjs`。** 方法是：把渲染出的球体截图放进同一套相机模拟里测试，然后再上真机。

## 编码融合：方案 A 与方案 B 对比（2026-11-23，模拟测试）

**测试方法**
- 画面：`docky-bubble.exe` 实际渲染的动画帧，尺寸 560×560，帧率 15 帧/秒。
- 背景：影棚灰背景、Windows 自带壁纸，两种都测。
- 相机：经过 `camera-sim.mjs` 模拟，包括透视、失焦、噪声、反光、摩尔纹、手抖。
- 测试脚本：`web/test/compare-ab.mjs`。
- 对比图：`docs/media/optical-bubble/compare-ab.png`。

**A：编码做成玻璃里的光**
- 外观：
  - 亮格连成柔和的光弧，带轻微色散，跟着涟漪轻微晃动；
  - 外圈是球体自身的亮边，内圈是一圈光环；
  - 暗的部分是被压暗的玻璃，球外一圈是柔和的阴影；
  - 球的核心部分保持原样。
- 显示编码时，球体的大幅晃动会收小，涟漪照常。
- 单帧解码结果，每种条件 16 次：
  - 正对、小尺寸、失焦、暗光、反光、摩尔纹：两种背景都是 16/16；
  - 倾斜 25–40°：影棚背景 7/16，壁纸背景 12/16（每帧单独计算；扫描页每秒约解码 10 帧）；
  - 没有读错过。
- 为了支持 A，解码器做了两处改动（Phase 1 的全部测试仍然通过）：
  - 新增"找编码自身的外圈"，以前只找"亮圆盘 + 暗背景"，现在背景亮时也能找到；
  - 拟合外圈和内圈时，只在估计位置附近搜索，不会再被数据光弧的边缘带偏。

**B：隐形水印（亮度按比例上下浮动）**
- 读法：多帧对齐、平均、高通，再用 v1 解码器读。
- 为了得到上限，几何参数直接取 A 在同一视角下解出的结果，相当于已经完美定位：
  - ±4%、±8%、±15%、±25%、±40%，平均 1、8、24 帧，全部读不出；
  - 同样的读法用在 A 上能读出，所以测试方法本身没问题。
- 原因：
  - 多帧平均只能消掉会动的部分（涟漪、焦散）；
  - 球体静止的部分（倒过来的背景、轮廓、高光）亮度变化远大于水印；
  - 而且按比例浮动，在暗的地方几乎没有变化。
- 另外，在平滑的浅色背景上，±4% 就已经能看出格子和外圈的阴影环，并不真正隐形。
- 没测过的可能：专门设计的扩频编码（码位更少，用全图相关来检测），可能比 v1 布局好。但"静止背景不会被平均掉"这个根本问题仍然存在。
